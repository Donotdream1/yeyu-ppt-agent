# 软件说明书与源程序材料

本目录以“叙帧智能演示文稿生成与协作系统 V0.1.0”为软件名称与版本，提供与实际功能对应的使用说明书、可复核的程序清单生成方法，以及材料核对项。仓库包版本是0.1.0，未把其他项目样例中的V1.0作为本软件版本。

2026年10月30日起产品品牌更新为“叙帧（Xuzhen）”。此前已发布的Word附件与源码清单保留对应历史名称及提交，不自动改写。以新名称提交材料时，应从新版本重新提取源码并生成文档，更新目录、页码及截图后再检查，不能混用旧版清单和新名称。

## 文件与维护方式

- [完整使用说明书](manual/software-manual.md)：安装、账号、项目、文档输入、模板、模型、生成、逐页编辑、素材、Skills、协作、回收站和维护。
- `manual/screenshots/`：隔离示例账号与数据下采集的实际软件界面，采集不调用模型、不读取生产账号和作品。
- `scripts/prepare-source-listing.mjs`：只从声明范围内的Git跟踪文件准备源程序，记录源文件顺序、原文件SHA-256、显示规范化校验值和提取区间。
- `scripts/build-software-docs.py`：将说明书和程序清单导出为Word，名称与版本从清单读取。
- `scripts/render-manual-word.ps1`：Windows上用Microsoft Word更新目录及页码并导出PDF供检查，不关闭用户其他文档。

Word交付文件在`artifacts/software-docs/`，预览与校验数据在`test-output/copyright-docs/`。这些生成目录默认不提交Git，避免把本机导出结果误作为不断变化的源文件。公开仓库保留可阅读的说明书、截图、工具及材料规范；需要发布Word时，在审核后作为对应GitHub Release附件上传。

## 一般交存规则依据

《计算机软件著作权登记办法》第十条规定，程序和文档通常交存前、后各连续30页；不足60页提交全部。除特定情况外，程序每页不少于50行，文档每页不少于30行。第十七条要求使用国际标准A4纸。依据：[国家版权局登记办法的商务部法规库文本](https://ipr.mofcom.gov.cn/law/detail.shtml?id=1767)。

北京市版权局公开办事指南还说明，材料名称与版本应一致，分别连续标注页码，文档有图等情况按其说明处理。提交时应核对实际受理渠道的现行要求；不能只因为源码文档恰好60页，就判断所有登记条件已经满足。参考：[北京市政务服务办事指南](https://banshi.beijing.gov.cn/pubtask/task/1/110000000000/3e283672-76be-4c8c-98e8-0bebe9bd06bf.html?locationCode=110000000000&serverType=1002)。

## 源程序范围与可追溯性

程序清单从当前网页入口`src/bootstrap.jsx`和服务端入口`server/index.mjs`追踪可达依赖，包含实际使用的自有前端业务代码、样式、服务端实现，并加入Hermes调用适配器和Office桥接脚本。排除未被当前入口引用的早期原型、node_modules、Hermes上游、引入的第三方Skills、shadcn基础组件、测试、用户运行数据和密钥。排除第三方代码不等于这些依赖没有权利或许可要求，依赖及声明仍见[第三方说明](../THIRD_PARTY_NOTICES.md)与[许可证](../LICENSE)。

源码按确定顺序组织为完整的自有程序集合，再提取开头1500与结尾1500条显示行，每页50行，共60页。不是任意挑选60页代表性片段，也不复制样例项目代码。JS、JSX和CSS仅在导出显示时规范化排版；空行不计入显示行，长行仅在材料中折行，业务语句不改写。完整可执行源码以清单关联的Git提交及原文件校验值为准。

生成前应保持工作区源码与对应提交一致；有未提交业务改动时，先审核并提交，再提取。程序最后一页到达所声明程序集合的实际末尾。材料中的文件清单、提取区间和版本应与最终公开提交一起保存，不能在材料完成后替换源码却继续使用旧清单。

## 重新生成

先构建网页，再采集示例截图，最后准备源程序并用安装了python-docx的文档环境导出。源码读取与排版工具不访问模型API。

```powershell
npm run build
node scripts/capture-manual-ui.mjs
node scripts/prepare-source-listing.mjs
python scripts/build-software-docs.py
```

Word排版完成后还应渲染检查。Windows环境可以使用本项目的Word脚本，其他环境可使用文档处理环境提供的渲染工具。更新目录与页码会改变Word包内缓存，不改变关联Git提交中的源程序。

使用Word脚本的`-UpdateFields -SanitizeMetadata`选项，可以在更新目录页码后将文档作者和最后修改者统一为项目文档标识，避免Office登录用户姓名进入公开附件。这是文档元数据处理，不代表已经确定著作权人。

文档Python依赖可通过`python -m pip install -r scripts/requirements-docs.txt`安装到单独环境。界面采集需要可用的Playwright浏览器环境。页面检查工具`verify-software-docs.py`读取Word包及原生渲染PDF，核查源码六十页和每页五十行、页边界及凭据模式。工具检查之外仍需逐页查看真实渲染效果。
