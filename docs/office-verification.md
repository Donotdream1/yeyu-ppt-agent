# 七类能力：职责与模拟验收

日期：2026-10-30。新入口 `/workbench`；PPT保留 `/workspace` 和旧演示稿链接；六个办公页面为 `/office/writing`、`/office/tasks`、`/office/summary`、`/office/meeting`、`/office/sheet`、`/office/review`。`/office`保留为六能力组合视图。

## 分层框架

1. React + shadcn/ui：七能力工作台、独立输入/结果页面、统一导航与设置。
2. 账号与权限：复用现有登录和模型连接；团队采用成员名单；个人资料、连接、文稿和运行记录按账号隔离。
3. Hermes：所有语义模型调用经真实Python `AIAgent`；按能力加载本地Skill及GitHub适配依据；工具返回结构由Zod验证。
4. 受限工具：PPT原生组件、白名单表格操作、文稿/报告导出、IMAP/SMTP、ASR接口、任务与收集。模型没有任意终端、网络发送或文件删除权限。
5. 持久化：现有PPT数据保持原结构；新办公资料、任务、活动、通知、密文连接和作业位于 `data/office/`；原始工作簿数据与新结果分开保存。
6. 运行台：PPT与办公任务分别呈现执行记录、错误、停止与真实工具提交，不把模型私有推理当执行日志。

## 验证命令与范围

- `npm test`：包含现有系统回归和14项办公测试。部分依赖私有素材的既有用例仍按原说明跳过，不伪称已覆盖个人库的全部页面。
- 本次结果：288项中277项通过、0项失败、11项跳过；当前`npm audit`报告0个已知告警。
- `node scripts/verify-office.mjs`：隔离目录、合成账号、真实Hermes Python进程、本地模拟模型服务。六个GitHub Skill适配都实际进入模型上下文，`submit_office_result`在真实工具日志中确认成功；HTTP权限和文件下载同时验证。
- `node scripts/verify-office.mjs --ui-only`：七张能力卡、PPT入口、六办公面板、独立评审URL、390px移动布局、连接设置、Skills来源弹窗和Hermes办公运行记录，无前端异常。
- `node scripts/verify-template-office.mjs --fallback`：使用合成可编辑模板完成实际Office检查，不读取用户私有模板和作品。
- `npm run build`、`npm run check:publication`、`npm audit`：构建、公开文件检查及当前依赖审计。ExcelJS的uuid间接依赖以兼容CommonJS的11.1.1覆盖，解决旧版已知告警；工作簿读写测试覆盖此组合。

这些是功能和集成模拟，不是内容质量基准测试。真实邮件送达、真实录音识别准确率、企业IMAP权限、实际文档审查质量，需要配置真实服务并由用户核对。测试没有连接真实邮箱、上传真实会议音频或使用付费模型，也没有发送外部消息。
