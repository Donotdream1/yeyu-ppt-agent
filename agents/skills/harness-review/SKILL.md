本适配器基于 [固定版本来源与采用说明](references/adoption.md)。先阅读该文件，再调用 ppt_audit_skills。上游工具属于办公自动化与PPT审查，不是通用技能评分器，不得把局部静态检查描述成完整语义审核。

检查执行链：需求与证据 → 页面方案 → 素材及配色分析 → 原生布局 → 原文与数据校验 → 渲染测量 → 交付。每阶段输出必须可验证，失败只修正相关页，已通过的页保留。

按五维报告：visual（字体、对比、结构、占比）、pedagogy（叙事和逻辑关系）、proofreading（术语、文案、溢出）、parity（实际请求的输出格式一致性）、substance（数据、引用、结论依据）。对未执行的 PDF 一致性、未提供参考图的像素复刻等，标记未检查，不给虚假通过分。

科研模式使用用户指定的32/21/17/14pt层级，不能照搬上游36/24pt商务字号。采用素材或明确用户配色，不能加载上游预设覆盖用户颜色。图表、表格和结构保持原生编辑，不采用上游截图背景/图片图表作为默认输出。不得结束用户的WPS或Office进程，仅打开、检查和关闭本应用自己的临时文档。

发布前执行 ppt_review_layout 和 ppt_harness_review，解决 error；有材料限制时保留明确 warning。最后 ppt_publish 生成真实文件。报告区分“规则检查通过”“PowerPoint测量通过”和“人工视觉审核”，不得互相替代。

同时采用[外部验收方法](../ppt-writing/references/upstream-design-notes.md)：核对designLock与成稿是否一致，标题序列是否简洁连贯，原文事实是否被证据支持。对失败或未执行的检查保留状态，不给空白通过；修复使相关旧结论失效后须重查。模板、部分页面及共享资源的变更范围分别记录，未改页应做回归核对。

发布前跨页核对sourceId＋page唯一性与目录章节映射，逐页检查日期/事件配对、父子标题层级、混合字号与容器中心。结束页必须完整来源于结束用途素材，普通正文母版的导航、年份或标题不可残留。明确区分原生对象保留和文字视觉正确，两者都须验证。

将主题关联作为独立发布条件：ppt_review_content须通过。过期签名不能沿用；内容或素材修改后复审，纯字体或对齐修改不重写准确文案。对关联弱的模块先改写，结构不符则换材；不可把合理缩写和归纳误判为无关。
